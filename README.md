# FlyRank A8 - Automated PDF & Email Reports

## Project

This project generates PDF reports from a SQLite database containing books scraped from Books to Scrape.

The report includes summary statistics, the five most expensive books, books grouped by rating, and the complete book list.

## Data Source

Website:

https://books.toscrape.com/

The database contains 60 books from the first 3 catalogue pages.

## Report Contents

Each generated PDF contains:

- total number of books
- average book price
- top 5 most expensive books
- number of books by rating
- complete list of books

## Database

The project uses SQLite.

Database:

```text
report.db
```

The database contains:

- `books` - scraped book data
- `reports` - generated report metadata and file paths

The seed script is repeatable and does not create duplicate book records.

## Aggregation

The report generator performs SQL aggregation queries for:

- total book count
- average price
- top 5 most expensive books
- books grouped by rating

The queries are performed directly against the database rather than using an N+1 query pattern.

## PDF Generation

PDFs are generated from HTML using Playwright and Chromium.

Generated reports are stored in:

```text
reports/
```

Each report is saved with its report ID:

```text
reports/1.pdf
reports/2.pdf
```

The generated PDF contains clean page breaks between report sections and can be opened as a normal PDF document.

## API

The API is built with FastAPI.

Start the API with:

```powershell
python -m uvicorn src.api:app --reload
```

The API runs on:

```text
http://localhost:8000
```

### Health Check

```http
GET /health
```

Example:

```powershell
curl.exe -i http://localhost:8000/health
```

Expected response:

```json
{
  "status": "ok"
}
```

### Generate a Report

```http
POST /reports
```

Example:

```powershell
curl.exe -i -X POST http://localhost:8000/reports
```

If no report has been generated today, a new report returns HTTP `201 Created`:

```json
{
  "id": 1,
  "file": "/reports/1/file"
}
```

If a report has already been generated today, the existing report is returned with HTTP `200 OK`.

### Get Report Metadata

```http
GET /reports/{id}
```

Example:

```powershell
curl.exe -i http://localhost:8000/reports/1
```

The response contains:

- report ID
- stored file path
- creation time
- file endpoint

Example:

```json
{
  "id": 1,
  "path": "C:\\flyrank-a9\\scraper\\pdf-report-generator\\reports\\1.pdf",
  "created_at": "2026-09-15T09:50:25.825537+00:00",
  "file": "/reports/1/file"
}
```

### Download the PDF

```http
GET /reports/{id}/file
```

Example:

```powershell
curl.exe -i http://localhost:8000/reports/1/file
```

The endpoint returns the generated PDF with:

```text
Content-Type: application/pdf
```

Unknown report IDs return HTTP `404 Not Found`.

## Idempotency

`POST /reports` checks whether a report has already been generated today and reuses the existing report instead of generating another PDF.

This idempotency check protects against duplicate report generation when the same request is submitted more than once.

A real-world example is preventing the same customer from receiving the same report email twice, which could cause duplicate notifications and unnecessary costs.

### Normal Request

Run:

```powershell
curl.exe -i -X POST http://localhost:8000/reports
```

If today's report already exists, the API returns HTTP `200 OK` with the existing report ID and file link.

For example:

```json
{
  "id": 2,
  "file": "/reports/2/file"
}
```

Sending the same request again returns the same report ID and does not generate another PDF.

### Force a New Report

A fresh report can be generated by sending:

```json
{
  "force": true
}
```

Example:

```powershell
curl.exe -i -X POST http://localhost:8000/reports -H "Content-Type: application/json" --data-binary '{"force":true}'
```

The `force` option skips the daily idempotency check and creates a new report.

The forced request returns HTTP `201 Created`.

## Verification

The implementation was verified with:

- `GET /health` returning `200`
- `POST /reports` generating a PDF
- `GET /reports/{id}` returning report metadata
- `GET /reports/{id}/file` serving the PDF
- unknown report IDs returning `404`
- repeated normal `POST /reports` requests returning the same report ID
- repeated normal requests not creating another report file
- `force: true` creating a new report
- SQLite report records confirming the generated reports

## Running the Project

### 1. Activate the virtual environment

```powershell
.\venv\Scripts\Activate.ps1
```

### 2. Seed the database

```powershell
python -m src.seed
```

The database should contain 60 books.

### 3. Test the report aggregation

```powershell
python -m src.test_report
```

### 4. Start the API

```powershell
python -m uvicorn src.api:app --reload
```

### 5. Generate a report

In another PowerShell window:

```powershell
curl.exe -i -X POST http://localhost:8000/reports
```

### 6. Open the generated PDF

Use the returned file endpoint:

```text
http://localhost:8000/reports/{id}/file
```

## Responsible Scraping

Books to Scrape is a public practice sandbox for learning web scraping.

The scraper is limited to the first 3 catalogue pages and is expected to collect 60 unique books.

The scraper collects:

- title
- product URL
- price
- availability
- rating
- description
- source page
- fetch time

The site's `robots.txt` URL returned HTTP 404 Not Found when checked.

This scraping code should not be reused on another website without checking that site's rules and terms first.
